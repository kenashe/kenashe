# Architecture

How kenashe.ai is built and operated. Companion to [PROJECT.md](PROJECT.md) (setup) and
[DECISIONS.md](DECISIONS.md) (why).

---

## System map

```
                    ~36 RSS/API feeds  (DATA_SOURCES.md)
                              │
                    ┌─────────▼──────────┐
   GitHub Actions   │  pipeline/src/     │      Postgres + pgvector
   cron 0 13 * * *  │  run.ts            │◄────►  covered / items / runs
                    └─────────┬──────────┘        (dedup memory)
                              │ commits .mdx + images
                    ┌─────────▼──────────┐
                    │  master branch     │──── Vercel build ────► kenashe.ai
                    └────────────────────┘
```

Two independent halves that meet at the repo: the **pipeline writes files**, the **site
builds files**. There is no runtime API, database call, or server in the published site —
it is fully static.

## The site

Astro 6, Tailwind 4, MDX, statically generated, deployed on Vercel (Hobby). Content is a
file-based Astro content collection at `src/content/blog/`, validated by the Zod schema in
`src/content.config.ts`.

Notable routes:

| Route | Source | Purpose |
|---|---|---|
| `/blog/[...slug]` | `src/pages/blog/[...slug].astro` → `layouts/BlogPost.astro` | posts |
| `/topics/` + `/topics/[slug]` | `src/data/topics.ts` | the four beachhead hubs (see PRODUCT.md) |
| `/building/` | `src/data/building-cards.ts` | project cards |
| `/llms.txt`, `/llms-full.txt` | generated | LLM-oriented site summary |
| `/robots.txt` | generated | explicitly AI-crawler-friendly |

### Structured data (load-bearing for the LLM-discoverability goal)

`src/data/schema.ts` holds two canonical nodes — `personKenAshe` and `websiteKenAshe`.

- **Every content page emits a self-contained `@graph`**: page node + `BreadcrumbList` +
  `WebSite` + `Person`. This matters because single-page parsers (most LLM scrapers) do not
  crawl the homepage first to resolve an `@id` reference. See [DECISIONS.md](DECISIONS.md#d9).
- Posts additionally emit `citation` / `isBasedOn` (source provenance, from frontmatter
  `sources`) and `mentions` (entities with Wikidata `sameAs`, from frontmatter `entities`).
- **`personKenAshe` must stay byte-identical everywhere**, including the copy on
  luckydomains.io. Import it; never hand-copy it.

### Analytics & measurement

Two things run on every page from `BaseLayout.astro`, both cookieless:

- **Vercel Web Analytics** (`<Analytics />`, the `@vercel/analytics` package) — visits, page
  views, referrers, countries, devices. Dashboard: project → Analytics.
- **Vercel Speed Insights** (a plain `<script defer src="/_vercel/speed-insights/script.js">`)
  — real-user Core Web Vitals. Dashboard: project → Speed Insights. Loaded as a script rather
  than via `@vercel/speed-insights` deliberately: it is the same endpoint the package injects,
  and it avoids a dependency whose `package-lock.json` entry cannot be regenerated from the
  agent sandbox (npm is firewalled). Switch to the package if you add it with a real install.

Both are disclosed on `/privacy`. Search Console covers Google organic search only; the
**referrers panel in Web Analytics is where AI-assistant traffic shows up** (`chatgpt.com`,
`perplexity.ai`, `claude.ai`, …), which is the payoff metric for the discoverability work.

### Related posts

`src/data/related.json` is a slug → related-posts map regenerated by the pipeline each run
from the pgvector embeddings (top 5, cosine ≥ 0.4). The site renders it as a Related block
and as `relatedLink` in the Article schema. No API calls at build time.

## The pipeline

Entry point `pipeline/src/run.ts`. One pass, in order:

| # | Stage | File | Notes |
|---|---|---|---|
| 1 | **ingest** | `ingest.ts` | Six connectors: `rss`, `youtube`, `arxiv`, `github_releases`, `hackernews`, `reddit`. De-dupes by source id against the `items` table. Logs `[ingest] <name>: <n> items` per source. |
| 2 | **embed** | `llm.ts` | OpenAI `text-embedding-3-small` (1536-dim). Falls back to a lexical embedder when `OPENAI_API_KEY` is absent, so dev runs work. |
| 3 | **cluster** | `core.ts` | Greedy cosine clustering at `CLUSTER_SIMILARITY` (0.78) → "stories". |
| 4 | **dedup** | `core.ts` | Each story vs. covered memory at `DEDUP_SIMILARITY` (0.82). This is the core fix over the old n8n pipeline, which wrote a topic history it never read. |
| 5 | **rank** | `run.ts` | `rankScore = Σweight + 0.5 if any tier-1 item + 0.15×min(items,5)`. |
| 6 | **select** | `run.ts` | See "Selection" below. Logs `[select] reserved -> ...`. |
| 7 | **synthesize** | `synthesize.ts`, `prompts.ts` | Tier-appropriate model writes MDX. Records `sources` + detected `entities` into frontmatter. |
| 8 | **gate** | `gate.ts` | A *different* model scores the draft 0–40 and lists critical fails. Pass → `draft:false`; fail → `draft:true` (auto-drafted, never deleted). |
| 9 | **images** | `images.ts` | Hero + inline images; art direction rotates per slug. Skipped unless `IMAGES_ENABLED=1`. |
| 10 | **publish** | `publish.ts` | Writes MDX, regenerates `related.json`, commits, pushes, pings the Vercel deploy hook. |
| 11 | **digest** | `run.ts` | Telegram summary. A hard failure sends a plain-text error ping. |

### Selection

Daily budget: `DAILY_FLAGSHIPS` (3) + `DAILY_NOTES_MAX` (7) ≈ 10 posts.

Three **reserved slots** are taken off the top, because these beachheads are tier-2 and
single-source and would otherwise never outrank an arXiv paper on merit:

- 1 domains story, 1 crypto story (`DA_DOMAINS` / `DA_CRYPTO` source sets)
- 1 marketing story (`MK_SOURCES`)

Reserved picks come out of the notes budget, so total volume stays flat. Each is still
gated — **a slot is not a publish**. After synthesis they get canonical beachhead tags
(`digital-assets` + `domains`/`crypto`, or `marketing-ops`) so they land in the right hub.

`withCanonicalTags()` additionally maps tag aliases onto canonical hub tags
(e.g. `agentic` → `ai-agents`).

### The weekly deep-dive (pillar)

Config: `pipeline/config/deepdive.json`.

```json
{ "enabled": true, "weekday": 2, "minStories": 2, "maxStories": 3, "force": false }
```

On the configured weekday (2 = Tuesday) a **pillar** replaces one flagship slot: 1800–2600
words, multi-source, spoke-linked to 8 related posts, gate bar 31 (vs 30 flagship / 27 note).

Selection rules, in order:
1. Rotate beachheads by `isoWeek % 4`.
2. A beachhead is **eligible** only with ≥ `minStories` stories **and** ≥1 story anchored by
   a *primary* source (`tier === 1 || primary === true`). Commentary can never anchor a
   pillar, no matter how many sources corroborate it — see [DECISIONS.md](DECISIONS.md#d7).
3. If the rotation pick is ineligible, fall back to the **least-recently-covered** eligible
   beachhead (derived from published posts' frontmatter — the repo is the state).
4. If nothing qualifies, **skip** and run a normal day.

Logs `[deepdive] <bh> pillar from N primary stories | <counts>` or
`[deepdive] skipped: ... | <counts>`, where counts read `beachhead:total(Np)`.

`force: true` is a **shadow-only** test override; it can never publish off-schedule.

## Data store

Postgres + pgvector (`STORE_BACKEND=postgres`), schema in `pipeline/db/schema.sql`:

| Table | Purpose |
|---|---|
| `items` | every ingested source id — the exact-dup guard. `markSeen` inserts ids only; the other columns exist for future use. |
| `covered` | published posts + `vector(1536)` embedding. Powers dedup *and* related-posts. ivfflat cosine index. |
| `runs` | per-run JSON report, for observability. |

Dev uses `JSONFileStore` (`STORE_BACKEND=file`) — same interface, a local JSON file.

Apply the schema with `psql "$DATABASE_URL" -f pipeline/db/schema.sql` (idempotent).

## Models

`pipeline/src/config.ts` → `MODELS`. A **different model gates than drafts**, deliberately,
so the review is independent.

| Stage | Model |
|---|---|
| flagship + deep-dive prose | `claude-opus-4-8` (Anthropic) |
| notes | `gpt-5.5` (OpenAI) |
| gate | `gpt-5.5` (OpenAI) |
| triage / alt-text | `deepseek-chat` |
| embeddings | `text-embedding-3-small` |
| images | OpenAI `gpt-image-1` |

⚠️ **Known wart:** `MODELS.image` says `gemini-3-pro-image`, but `images.ts` calls OpenAI
`gpt-image-1` directly and ignores that config. Likewise `config.IMAGES` is unused —
image count is driven by `{{IMAGE:inline:...}}` placeholders in the prompt output. Harmless
but misleading; fix or delete if you touch that area.

## Deployment & operations

### Site
Vercel builds `master` automatically. Build ~8–10 min at current post count.
**Commits must be authored `Ken Ashe <kenashe@gmail.com>`** or Hobby skips the deploy.

### Pipeline
GitHub Actions, `.github/workflows/pipeline.yml`. `pipeline/ci/pipeline.yml` is a template
copy: a fine-grained PAT without `workflows` scope **cannot push to `.github/workflows`**,
so agents edit the template and a human copies it across. If the two differ,
`.github/workflows` is what actually runs.

> ⚠️ **Pending copy:** the template adds a `Test` step (`npm test`) after `Typecheck`. Copy
> `pipeline/ci/pipeline.yml` over `.github/workflows/pipeline.yml` to activate it in CI.

- Gate: repo **variable** `PIPELINE_ENABLED` must equal `true`.
- `schedule` → **live**; `workflow_dispatch` → dropdown, default **shadow**.
- Modes: `live` (`npm run run:once`), `shadow` (`run:shadow`), `backfill`.
- Concurrency group `content-pipeline`, no cancel-in-progress.

### Runbook

**Pause everything:** set `PIPELINE_ENABLED` to `false`. No code change, no revert.

**A run failed.** Check the Actions log:
- Failure at *"Set up job"* with "Failed to resolve action download info" = GitHub
  infrastructure, not your code. Check githubstatus.com and wait.
- Failure inside *Run* = read the Telegram error ping or the job log. Nothing is marked
  seen until ingest completes, so a failed run loses nothing — the next run picks the
  stories up.

**A bad post broke the Vercel build.** Content errors surface only at build time (see
[DECISIONS.md](DECISIONS.md#d5)). Fix or delete the offending `.mdx` on `master`; the
sanitizers should prevent recurrence.

**Preview changes safely:** manual dispatch in `shadow` mode → drafts land on the
`pipeline-shadow` branch, force-pushed each run, publishing nothing.

**Rotate a key:** update the secret in Settings → Secrets and variables → Actions. No code
change. For `DATABASE_URL` also confirm pgvector is enabled on the new instance.

**Change run shape** without touching code: `DAILY_FLAGSHIPS`, `DAILY_NOTES_MAX`,
`DEDUP_SIMILARITY`, `CLUSTER_SIMILARITY`, `RELATED_K`, `RELATED_MIN_SIM` are all env vars;
gate thresholds and models are in `config.ts`; feeds in `sources.yaml`; pillar cadence in
`deepdive.json`.

## Testing

`cd pipeline && npm test` — Node's built-in runner (`node:test`), no dependencies, no
network, no keys. Covers the pure logic: YAML/MDX escaping (both caused production
outages), slug/tag governance, cosine + related-post selection, clustering/dedup, entity
detection, and the selection/rotation math. CI runs it before every pipeline run.
